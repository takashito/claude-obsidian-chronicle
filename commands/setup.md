The user wants to configure the `obsidian-chronicle` plugin. Your job: generate a `.env` file in either the **plugin root** (applies everywhere) or the **current project root** (applies only when Claude Code is launched here).

# Steps (follow in order, do not skip)

## 1. Resolve the two candidate destinations

- **Plugin root**: read `~/.claude/settings.json` and extract `.extraKnownMarketplaces["obsidian-chronicle"].source.path` with jq. If not registered, abort with a clear message telling the user to install the plugin first.
- **Project root**: `$(pwd)` — the current working directory of this Claude session.

```bash
jq -r '.extraKnownMarketplaces["obsidian-chronicle"].source.path // empty' ~/.claude/settings.json
pwd
```

## 2. Ask where to save

Use AskUserQuestion (single-select):

- **Plugin root** (`<plugin-path>/.env`) — applies to every project. Recommended for the global default.
- **This project** (`<pwd>/.env`) — applies only when Claude is launched from this dir. Overrides the plugin .env when both exist.

If the user picks the project location but the project already has a `.env`, **show how many non-OBSIDIAN keys it currently has** (using `grep -c '^[A-Z]' <pwd>/.env` then subtract OBSIDIAN ones — or just say "the file already has other keys; the plugin will leave them untouched"). Then proceed.

## 3. Check for existing config at the chosen location

If `<chosen>/.env` already exists:
- Read it.
- Show ONLY the OBSIDIAN_* lines (use `grep '^OBSIDIAN_' <file>`).
- Use AskUserQuestion: **Overwrite OBSIDIAN keys** / **Cancel**.

If overwriting: preserve every non-OBSIDIAN line in the file. Only the OBSIDIAN_* lines will be rewritten. Do NOT touch unrelated keys like DB_PASSWORD, API_KEY, etc.

## 4. Read .env.example for the canonical key list

Read `<plugin-root>/.env.example`. The keys listed there are the only ones to write. Do not invent extra keys.

## 5. Gather settings via AskUserQuestion (one batched call, 4 questions)

For each, default = existing value at the chosen file if present, else value in `.env.example`.

1. **Sessions directory** (`OBSIDIAN_SESSIONS_DIR`) — Header: `Sessions dir`. Options: the default (recommended), `~/obsidian/sessions`, `~/Notes/Claude Sessions`.
2. **Daily Notes directory** (`OBSIDIAN_DAILY_DIR`) — Header: `Daily dir`. Options: default `<sessions-dir>/Daily Notes` (recommended), `~/obsidian/Daily Notes`.
3. **Summarization model** (`OBSIDIAN_CHRONICLE_MODEL`) — Header: `Model`. Options: `haiku` (recommended), `sonnet`, `opus`.
4. **Log file path** (`OBSIDIAN_CHRONICLE_LOG`) — Header: `Log path`. Options: default (recommended), `~/.claude/logs/obsidian-chronicle.log`.

If the user picks "Other", take their string verbatim.

## 6. Write the file

**If creating a new file** at the chosen location, write:

```
# obsidian-chronicle configuration
# Generated by /obsidian-chronicle:setup on YYYY-MM-DD

OBSIDIAN_SESSIONS_DIR=<value>
OBSIDIAN_DAILY_DIR=<value>
OBSIDIAN_CHRONICLE_MODEL=<value>
OBSIDIAN_CHRONICLE_LOG=<value>
```

**If updating an existing project .env** that contains other keys:
- Read the full file.
- For each of the 4 OBSIDIAN keys: replace its line if present, else append at the end under a `# obsidian-chronicle` header comment.
- Leave every other line exactly as-is. Preserve blank lines and ordering of non-OBSIDIAN content.

Use the user's answers verbatim — do NOT expand `~` to `$HOME` (the script handles tildes).

## 7. Confirm

Print one line: `✓ wrote <chosen-path>/.env`.

Then show:
- The 4 chosen settings as a markdown bullet list.
- The precedence note: "This file overrides the plugin .env at <plugin-root>/.env when Claude runs in this project" (only if user picked project root) — OR — "This file applies to every project unless a per-project .env at $CWD overrides it" (only if user picked plugin root).

Mention that the new config takes effect on the next hook fire (SessionEnd, PreCompact, or `/done`) — no restart needed.

# Rules

- Be terse. No long explanations of what the plugin does.
- Don't run extra commands beyond what the steps require.
- Don't modify any file other than the chosen `.env`.
- Don't touch `.env.example` (it is the canonical template).
- If editing a project .env, never read or echo non-OBSIDIAN lines back to the user — those may be secrets.
